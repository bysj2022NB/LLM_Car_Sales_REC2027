# 新能源智选——新能源汽车销售分析与推荐系统介绍 

## 1. 系统概述

“新能源智选”是一套面向新能源汽车消费者和汽车数据管理人员的销售数据分析与购车推荐系统。系统以 MySQL 中的车型、销量、评分和用户评论数据为基础，使用 Pandas、NumPy 完成数据清洗、统计分析、指标标准化和推荐计算，并通过 Flask 向用户端和管理端提供服务。

系统主要解决以下问题：

- 汽车参数、价格、销量与口碑信息分散，消费者难以快速形成统一判断。
- 不同预算区间内车型数量较多，仅比较单一价格或评分容易产生片面结论。
- 传统排行榜缺少个性化能力，无法体现用户对空间、舒适、动力等属性的不同偏好。
- 数据分析结果专业性较强，普通用户不容易理解推荐分数和车型之间的取舍。

为此，系统围绕“数据分析、性价比推荐、车型对比、AI 辅助决策、后台管理”五个方面展开建设。游客可以浏览车型与公开分析数据；普通用户登录后可以收藏、评分、保存购车偏好并获得个性化推荐；管理员可维护车型、销量、评论和推荐权重，并查看运营数据与系统日志。

## 2. 建设目标

系统的总体目标是将原始汽车数据转化为可理解、可比较、可追溯的购车建议：

1. 建立统一的新能源汽车数据展示平台，集中呈现车型价格、销量、评分、评论和能源类型。
2. 为 10 万以内、10—20 万、20—30 万、30—40 万及自定义预算用户提供性价比推荐。
3. 结合用户收藏、评分和属性偏好，形成具有差异化的个性化推荐结果。
4. 使用图表展示销量排行、品牌份额、价格分布、月度趋势和评论情感等统计结果。
5. 引入大语言模型解释推荐和对比结论，降低数据分析结果的理解门槛。
6. 通过角色权限、操作审计、缓存和错误降级机制，保证系统适合本地部署和毕业答辩演示。

## 3. 数据基础

系统使用项目提供的 `db_car.sql` 作为原始数据源，并在不破坏原始文件的前提下扩展业务数据表。经初始化和数据检查，系统数据规模如下：

| 数据类型 | 数量或范围 | 用途 |
| --- | ---: | --- |
| 车型数据 | 290 款 | 车型展示、筛选、评分与推荐 |
| 销量车型 | 290 款 | 销量热度、榜单和品牌分析 |
| 用户评论 | 18,883 条 | 好评率、情感分析和口碑摘要 |
| 能源类型映射 | 290 条 | 纯电、插混、增程等分类筛选 |
| 月度销量 | 连续 12 个月 | 趋势图和销量变化分析 |

月度销量演示数据使用固定车型编号作为随机种子，结合季节系数和车型增长系数生成，最后一期与原始销量快照保持一致，因此数据生成过程可重复、结果可验证。后续也可以通过管理端导入真实 CSV 月销量数据进行覆盖。

## 4. 用户角色

### 4.1 游客

游客无需登录即可访问首页、车型中心、车型详情、数据分析、智能推荐和车型对比等公开功能，也可以使用 AI 选车助手了解预算、能源类型和用车场景之间的关系。

### 4.2 普通用户

普通用户在游客功能基础上，还可以：

- 收藏或取消收藏车型；
- 对车型提交 1—5 星评分；
- 保存预算、能源类型、车型类型和七维属性偏好；
- 查看个人收藏、评分与浏览历史；
- 在有效正向行为达到条件后获得个性化推荐。

### 4.3 管理员

管理员通过独立后台管理用户、车型、销量、评论、推荐权重和日志，可进行车型软下架、评论隐藏、用户禁用、CSV 销量导入、算法试算及 AI 运营洞察等操作。

## 5. 核心功能

### 5.1 首页与车型中心

首页集中展示系统核心数据、预算快捷入口、热门车型和主要分析图表。车型中心支持按关键词、品牌、预算、能源类型、车型级别和评分筛选，并提供分页与排序功能，帮助用户快速缩小选择范围。

### 5.2 车型详情

车型详情页展示价格区间、销量、综合评分、好评率、七维属性评分、评论情感、代表性评论和相似车型。用户登录后可以在该页面收藏车型或提交评分，还可以让 AI 根据近期评论生成口碑摘要。

### 5.3 智能推荐

智能推荐支持预设预算和自定义预算，并允许用户选择能源类型、车型类型以及价格、口碑、空间等关注程度。系统接收筛选条件后实时重新计算候选集和综合得分，返回推荐排名、七项分项指标及三条主要推荐理由。

### 5.4 个性化推荐

登录用户的收藏和高评分行为会用于构建用户偏好。当用户拥有至少 3 条收藏或 4 星以上评分等正向行为后，系统启用个性化模式：

> 最终得分 = 综合性价比分 × 70% + 用户画像余弦相似度 × 30%

用户明确给出 1—2 星的车型会从其主要推荐候选中排除，以减少与用户历史偏好相冲突的结果。行为不足时，系统使用购车问卷和综合性价比榜单完成冷启动。

### 5.5 车型对比

用户最多可选择 3 款车型，对价格、销量、评分、好评率、能源类型和七维属性进行横向比较。数据表负责展示精确数值，雷达图负责呈现属性差异，AI 对比顾问则进一步总结各车型优势、短板、适合人群和使用场景。

### 5.6 数据分析

系统使用本地 ECharts 展示以下分析内容：

- 车型销量排行榜；
- 连续 12 个月销量趋势；
- 品牌销量份额；
- 价格区间分布；
- 车型级别与销量分布；
- 价格与销量关系；
- 评论情感占比；
- 车型七维属性雷达图。

分析结果按照查询条件缓存，当车型、销量或推荐配置发生变化时主动失效，以兼顾响应速度和数据一致性。

### 5.7 AI 选车助手

系统接入火山方舟豆包模型，形成面向购车决策的 AI 辅助层，支持五类场景：

1. 解释推荐榜单和分项得分；
2. 总结 2—3 款车型的对比结论；
3. 归纳车型评论中的优点、问题和争议；
4. 根据预算、通勤距离、家庭人数和充电条件回答购车问题；
5. 为管理员生成销量、品牌、评论和数据风险方面的运营洞察。

AI 不直接修改推荐分数和排名。所有排序仍由 Pandas、NumPy 算法完成，AI 只将结构化计算结果转化为更易理解的自然语言建议。AI 未配置、超时或调用异常时，系统会返回确定性降级结论，不影响推荐、对比和分析等核心功能。

### 5.8 后台管理

后台包括管理驾驶舱、用户管理、车型管理、销量管理、评论管理、推荐权重配置、推荐试算、AI 运营洞察和系统日志。车型采用软下架，评论采用隐藏与恢复机制，避免硬删除破坏数据关联。所有关键管理操作均记录审计日志。

## 6. 推荐算法设计

系统首先使用 Pandas 合并车型、销量、评分、评论情感和月度销量数据，再使用 NumPy 完成缺失值处理、对数缩放、Min-Max 标准化和余弦相似度计算。

默认综合性价比权重如下：

| 指标 | 权重 | 说明 |
| --- | ---: | --- |
| 价格竞争力 | 25% | 比较预算范围内车型的最低价格 |
| 优惠幅度 | 10% | 根据价格区间中位数计算相对空间 |
| 综合及七维评分 | 20% | 综合总体评分和七维属性评分 |
| 贝叶斯平滑好评率 | 15% | 抑制少量评论造成的极端好评率 |
| 销量热度 | 10% | 反映市场接受程度 |
| 评价样本可信度 | 5% | 评论样本越充分，可信度越高 |
| 用户属性偏好匹配 | 15% | 衡量车型属性与用户偏好的相似度 |

算法采用以下处理提高结果可靠性：

- 销量和评论数量使用 `log1p` 缩放，降低头部车型对结果的过度影响。
- 好评率使用全站平均值作为先验，并以 20 条评论作为平滑强度。
- 评分为 0 的车型使用候选车型中位数参与计算，同时降低其评价可信度。
- 用户在推荐页调整价格、口碑和空间优先级时，系统会重新归一化本次请求权重并实时计算。
- 每条推荐均输出总分、七项分项指标和前三项突出理由，保证推荐过程可解释。

## 7. 系统创新点

以下内容属于本系统在本科毕业设计场景中的应用创新：

### 7.1 “确定性推荐 + 大模型解释”的双层架构

系统将可复现的数据算法与生成式 AI 分离：第一层负责预算过滤、指标计算和稳定排序；第二层负责推荐解释、对比总结和自然语言问答。该设计既利用了大语言模型良好的人机交互能力，又避免模型幻觉直接控制推荐结果。

### 7.2 融合价格、销量、评分和评论的多指标评价

系统不以最低价格、最高销量或最高评分作为唯一标准，而是将七类指标统一标准化并加权计算，使“性价比”由可量化的多维数据共同决定。

### 7.3 面向小样本评论的贝叶斯平滑

对于评论数量很少但好评率极高的车型，直接使用原始好评率容易造成排序偏差。系统引入全站平均先验和固定平滑强度，提高不同评论规模车型之间比较的公平性。

### 7.4 推荐结果可解释、可调节、可追溯

用户可以修改预算、能源类型、车型类型和关注重点，页面结果随条件实时更新。管理员可以调整七项推荐权重、执行算法试算并查看推荐日志。每次推荐都保留算法版本和结果车型编号，便于复核。

### 7.5 冷启动与行为个性化结合

新用户通过预算和偏好问卷获得综合推荐；当收藏和高评分行为积累到一定数量后，系统自动融合用户画像相似度，实现从规则推荐到个性化推荐的平滑过渡。

### 7.6 可复现的时间序列数据构造

在缺少完整历史月销量的条件下，系统采用固定随机种子生成连续 12 个月演示数据，并保证最后一期与原始快照一致。该方法兼顾了趋势分析演示、结果可复现和数据来源可说明性。

### 7.7 AI 安全与可靠性设计

API 密钥仅保存在服务端环境变量中，不进入前端、数据库或日志。系统还设置输入长度限制、评论不可信标记、调用限流、结果缓存、超时重试和错误降级，避免 AI 服务异常影响主业务。

## 9. 系统架构

系统采用分层和模块化设计：

```text
浏览器用户端 / 管理端
        │
        ▼
Jinja2 + HTML + CSS + JavaScript + ECharts
        │
        ▼
Flask 应用工厂与 Blueprint
├── auth：登录、注册、退出
├── main：页面与基础数据
├── user：资料、偏好、密码
├── api：推荐、分析、对比、收藏、评分、AI
└── admin：用户、车型、销量、评论、权重、日志
        │
        ▼
业务服务层
├── 推荐服务（Pandas / NumPy）
├── 数据分析与缓存服务
├── 能源类型分类与数据初始化
└── AI 辅助与错误降级服务
        │
        ├──────────────► 火山方舟豆包模型
        ▼
MySQL 8.0
```

应用采用工厂模式创建 Flask 实例，并通过 Blueprint 拆分认证、用户、后台和 API 模块。JSON 接口统一返回 `ok`、`data`、`message` 和 `errors` 字段，便于前端处理正常结果及错误状态。

## 10. 安全性与可靠性

- 写接口执行登录、角色和 CSRF 校验，防止越权操作和跨站请求伪造。
- 管理功能验证管理员身份，普通用户无法访问后台写接口。
- AI 密钥通过 `.env` 配置，只在 Flask 服务端读取。
- AI 问题最多 500 字，上下文和候选车型数量均有限制。
- AI 设置调用限流、15 分钟缓存、25 秒超时和异常降级。
- 车型使用软下架，评论使用隐藏机制，避免误删除关联数据。
- 分析结果设置缓存，并在数据或推荐配置修改后主动刷新。
- 后台操作、推荐请求和 AI 调用均保留必要审计记录。
